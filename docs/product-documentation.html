01 · EXECUTIVE SUMMARY

// 01 · EXECUTIVE SUMMARYThe 30-second pitch.

Atleato is a mobile fitness coaching app built around 5 distinct AI coach personas. Each persona changes the entire app — colors, programs, voice, nutrition rules. Buyers reserve a "Vanguard Pass" pre-launch for $1.99 (one-time, capped at 500 buyers). Launch target: Q3 2026 on Google Play.

SCOPE

What is built today

  • React Native mobile app: 41 screens, 6 nav tabs
  • 13 Supabase edge functions (AI + email + payments)
  • 11 database migrations (auth, workouts, nutrition, territory, waitlist, orders)
  • 12 live website pages (marketing + funnel)
  • Stripe-alternative Lemon Squeezy checkout, live
  • Resend transactional email pipeline, deployed
  • Real-time order ledger with 500-cap enforcement
  • Private Discord (founder + Vanguards)
NOT BUILT YET

Known gaps / roadmap items

  • iOS app (Android-first; iOS post-launch)
  • In-app purchases via Google Play Billing (Vanguard Pass uses Lemon Squeezy web-checkout for now)
  • Live multiplayer features (squads exist as solo UI)
  • Coach voice TTS in production (TTS engine wired in dev, voices being recorded)
  • Apple HealthKit integration
  • Public beta / closed-testing release

Most fitness apps give you a spreadsheet and a generic voice. 02 · POSITIONING

// 02 · POSITIONINGWhat Atleato is — and what it isn't.

Honest framing for investors, press, and partners. No "first-ever" or "world's only" claims.

2.1What it is

  • An AI-powered fitness coaching mobile app for Android (iOS post-launch).
  • Built around 5 distinct coach personas that each completely retune the app (colors, programs, voice, nutrition rules, ringtones).
  • A workout, nutrition, recovery, and territory-conquest super-app in one bundle.
  • Free forever for everyone, with a paid Legend tier ($19.99/mo) for premium features.
  • Currently in pre-launch waitlist mode with a 500-buyer Vanguard Pass ladder at $1.99 one-time.

2.2What it isn't

  • Not a personal trainer marketplace — no human coaches involved.
  • Not a video class library — no recorded workouts à la Peloton.
  • Not a social network — no public feed, no DMs, no follower graph.
  • Not a calorie counter alone — nutrition is integrated, not the headline.
  • Not a medical or clinical tool — no diagnosis, no insurance billing.

2.3Who it's for (and who it isn't)

CORE USER

Built for

  • Self-trained gym-goers (1–5 years experience)
  • Runners who want a goal beyond pace
  • People who skip workouts because their alarm gets snoozed
  • People who want a "coach voice" but can't afford a real trainer
  • Late-20s to mid-40s, Android-first markets (US, UK, IN, BR)
NOT BUILT FOR

Probably not for

  • Pro athletes with sport-specific coaches
  • Rehab / clinical patients (no medical claims)
  • Couch-to-5K absolute beginners (too intense)
  • Pure-bodyweight / yoga-only practitioners (gym-leaning programs)
  • Kids under 16 (age-gated)

2.4The honest moat

Each individual feature exists somewhere on the market (see Section 15 for the competitive teardown). Atleato's defensible position is:

  1. Combination depth — coaching + form + nutrition + territory + wake-up calls all in one app, all themed per coach.
  2. The 5 specific archetype personalities + their persona-driven UX swap.
  3. The brand DNA — dark + electric-lime + Anton-display typography, paired with the "Your Coach Calls" tone.
  4. Solo-built credibility — the founder reads every reply and ships every feature himself.
  5. The $1.99 / 500-cap Vanguard model — pre-launch validation with skin in the game.

3.2Coach IP & legal safety — honest disclosure

Earlier drafts of this doc claimed the coaches were "designed in-house to avoid IP collision." That claim has now been corrected. An external audit (June 2026) flagged that the original v1 personas used identity markers — catchphrases, accent descriptions, framing — that closely paralleled real public fitness figures. Those markers have been removed.

Current state: titles & bios use generic archetypes (The Sculptor, The Monument, The Analyst, The Commander, The Architect). Each coach now has an original full name (Marcus Stone, Titus Gold, Dr. Elena Voss, Drake Ironside, Dr. Kane Okoro). Identifying catchphrases have been replaced. Training methods (PPL, GVT, volume landmarks, RIR, periodization) are public-domain concepts and remain referenced generically.

Official disclaimer (use in all customer-facing materials): "Coaches are original fictional characters. Any resemblance to real persons, living or fictional, is unintended."

If any user, journalist, or athlete management agency raises an IP concern, the response policy is: acknowledge the parallel, rename or adjust within 48 hours, document the change. Legal review before scaling marketing or signing licensing deals (Section 9 / Athlete Licensing) is required.

06 · CORE WORKFLOWS

// 06 · KEY USER WORKFLOWSHow the app actually works.

Five end-to-end flows that define the Atleato experience.

6.1Workflow: Wake-up call

  1. User configures wake-up in coach-reminders (time, days, coach, ringtone)
  2. Local scheduled notification (via expo-notifications) fires at the chosen time
  3. Notification action launches deep-link to /incoming-call
  4. Full-screen call UI renders with pulsing avatar, coach's ringtone audio plays
  5. User taps Snooze → reschedules for +5 min · or Answer → opens today's workout in workout-lobby
  6. Streak counter increments; missed wake-ups log to recovery-checkin data

6.2Workflow: Live workout session

  1. User enters workout-session from lobby
  2. Exercise card shows: name, sets, target reps, RIR, last session's weight
  3. User completes a set → taps weight + reps + RIR → coach voice cue plays ("Quality reps. Stay humble.")
  4. Auto rest timer starts (90s, 120s, etc. per exercise config)
  5. 10s before rest ends, voice cue: "Get ready"
  6. On rest-over, vibration + voice: "Go" · timer transitions to next set
  7. If form-coach enabled, camera tracks 17 keypoints during set; live HUD shows knee/back angles, depth
  8. Session ends → routes to post-workout with session summary, PRs hit, share card
  9. If PR detected, pr-celebration animates with confetti + voice congrats

6.3Workflow: AI form correction

  1. User opens form-coach screen and selects exercise (squat, deadlift, bench, etc.)
  2. Camera permission requested; user sets phone at floor angle
  3. MediaPipe Pose Landmarker tracks 17 keypoints at ~30 FPS
  4. Frontend computes joint angles (knee, hip, back, elbow) per frame
  5. Telemetry overlay updates live (KNEE 94° · DEPTH DEEP · BACK -12°)
  6. If a "fault pattern" matches (e.g., knees-cave-inward), overlay turns red + voice plays correction in coach's signature voice
  7. Final form score computed (0–100) at end of set
  8. Legend-tier users get post-set video review via video-review screen

06 · CORE WORKFLOWS (CONT.)

6.4Workflow: AI food scanner

  1. User taps "Scan food" in (tabs)/nutrition → opens food-photo-scan
  2. Camera captures plate; image sent to analyze-food-photo edge function
  3. Function calls Claude vision API with the photo + structured prompt asking for foods, portions, and macros
  4. Response parsed into food items with estimated grams + calories + P/C/F
  5. User confirms or edits each item; saved to nutrition_log table
  6. Nutrition tab macro ring updates immediately

6.5Workflow: Territory conquest

  1. User taps "Start 5K run" from (tabs)/territory → opens run screen
  2. GPS tracking begins; user sees live pace, distance, route
  3. Each GPS coordinate is mapped to a "cell" — a 0.0018° × 0.0018° grid square (~200m²)
  4. As user crosses a cell, it's added to a local claim queue
  5. At run end, claim_cells() PG RPC validates the run (anti-cheat: rejects runs faster than 30 km/h sustained pace)
  6. Valid cells inserted into territory_cells table with owner_id and timestamp
  7. If a cell was previously owned by someone else, ownership flips and notify-steal edge function emails the previous owner
  8. Territory tab map refreshes via cells_in_bbox() RPC

6.6Workflow: Recovery-aware programming

  1. Each morning user fills recovery-checkin (5 sliders: sleep, soreness, stress, energy, motivation)
  2. Frontend computes a recoveryScore 0–100
  3. Edge function recovery-plan returns a volumeModifier (0.7–1.1) based on score
  4. Today's workout's sets/reps multiply by volumeModifier — e.g., recovery score 45 → 0.8× volume → fewer sets
  5. Coach voice cue acknowledges: "Going lighter today. Trust the process."
  6. If 3+ consecutive low scores, coach proposes a deload week in (tabs)/coach

6.7Cross-cutting: theming engine

When user switches active coach in profile, the global themeStore (Zustand) updates. Every component subscribes via useTheme() hook and re-renders with the new persona's color tokens, font weights, voice profile, and program templates. No app restart needed.

10.1Hidden / admin pages

Admin dashboard exists at an unguessable random-token URL (not published anywhere) plus tightened DB access. As of migration 012, the anon Supabase key can ONLY call waitlist_count() and vanguard_claimed_count() RPCs — it cannot SELECT row contents. Even if the admin URL leaked, no PII is exposed via the anon key. The token URL rotates whenever leakage is suspected.

10.2SEO & security

  • Sitemap: /sitemap.xml lists 7 public pages with priorities
  • Robots: /robots.txt allows all crawlers, disallows /admin*
  • JSON-LD: WebApplication schema on landing page
  • OG / Twitter cards: Set on showreel + index for social previews
  • Headers: CSP, X-Content-Type-Options, Referrer-Policy set via meta tags (browsers honor these). Limitation acknowledged: HSTS and X-Frame-Options are ignored by browsers when set via meta — they require real HTTP response headers, which GitHub Pages cannot configure. Plan: front the site with Cloudflare to set real HSTS/X-Frame-Options/Permissions-Policy headers before launch announcement
  • GDPR: Cookie consent banner on first visit; declines non-essential cookies by default

Form POSTs directly to Supabase /rest/v1/waitlist using public anon key. Row inserts with email + source ("landing-page" or "hero" or "...ref_friend@x.com"). Hero stat counter increments on next refresh.

Supabase DB webhook on waitlist INSERT calls send-welcome-email edge function. Function generates deterministic Vanguard Badge from email hash (e.g., "Obsidian Sentinel #042"), renders branded HTML + plain-text email, sends via Resend.

Front-end JS routes them with their email in query string. Upsell page shows: their position (#X on waitlist), real-time "X/500 claimed" count, 30-min reservation timer, 2 paths (pay $1.99 OR invite 3 friends free), 7 social-share buttons.

CTA href is the Lemon Squeezy checkout URL with the buyer's email pre-filled via ?checkout[email]=.... Lands on LS-hosted Stripe-like form. Pays $1.99 with card / Apple Pay / Google Pay.

Page detects ?paid=true, transforms CTA into green "✓ VANGUARD PASS CONFIRMED" banner. Clears 30-min reservation hold. Buyer's funnel complete.

16.2Security hardening applied

  • RLS enabled on every public table (migration 002)
  • Public schema grants revoked from PUBLIC role (migration 003)
  • LS webhook HMAC-SHA256 signature verified (constant-time compare, Web Crypto API)
  • Resend List-Unsubscribe RFC 8058 header on all emails
  • CSP + X-Frame-Options + Referrer-Policy on all HTML pages
  • HSTS enforced via GitHub Pages
  • Admin dashboard at random-token URL, not linked anywhere
  • No PII in URL query parameters except email-prefill (URL-encoded)
  • google-services.json, .env.local, all secrets in .gitignore
