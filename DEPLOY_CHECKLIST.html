Deploy Everything — One Sitting

All code is committed + pushed. This brings it live. Run from C:\Dev\fitai-pro-app. Phases A–B are required to launch the waitlist properly. C is optional native features (each needs an external account). D rebuilds the app.

Generate your secrets first — you'll paste them in several places below. On Windows, run this 3× and keep the outputs:
powershell -Command "[guid]::NewGuid().ToString('N')"
Label them: NOTIFY_STEAL_CRON_SECRET, DRIP_CRON_SECRET, and (if you don't already have it) confirm LEMONSQUEEZY_WEBHOOK_SECRET from the Lemon Squeezy dashboard.

Phase A — Database (2 min, no external accounts)

Applies every pending migration (014 squads fix, 015 referral count, 016/018 referral reward, 017 drip tracking). db push only runs un-applied ones — safe to re-run.

supabase db push

If it asks to link first: supabase link --project-ref kbldncrurztfwlqzajen

Phase B — Edge functions + secrets + cron (required for drip emails & security fixes)

B1. Set the secrets

supabase secrets set NOTIFY_STEAL_CRON_SECRET=<secret-1>
supabase secrets set DRIP_CRON_SECRET=<secret-2>
supabase secrets set LEMONSQUEEZY_VANGUARD_PRODUCT_IDS=<your-vanguard-LS-product-id>

Vanguard product id: Lemon Squeezy dashboard → Products → your Vanguard Pass → the numeric id in the URL. RESEND_API_KEY + LEMONSQUEEZY_WEBHOOK_SECRET should already be set from earlier; verify with supabase secrets list.

B2. Deploy the functions

supabase functions deploy send-drip-emails --no-verify-jwt
supabase functions deploy notify-steal --no-verify-jwt
supabase functions deploy lemonsqueezy-webhook

First two are cron-called (no JWT); the webhook is called by Lemon Squeezy with its signature.

B3. Schedule the cron jobs

Dashboard → Database → Cron Jobs → + Create. Two jobs:

Drip emails — daily · schedule 0 16 * * * (16:00 UTC) · SQL Snippet: 
SELECT net.http_post(
  url := 'https://kbldncrurztfwlqzajen.functions.supabase.co/send-drip-emails',
  headers := jsonb_build_object('Content-Type','application/json','x-cron-secret','<secret-2>')
);
Steal notifications — every minute · schedule * * * * * · SQL Snippet: 
SELECT net.http_post(
  url := 'https://kbldncrurztfwlqzajen.functions.supabase.co/notify-steal',
  headers := jsonb_build_object('Content-Type','application/json','x-cron-secret','<secret-1>')
);

If you already have a notify-steal cron from before, EDIT it to add the x-cron-secret header — otherwise it'll start returning 403.

Phase C — Optional native features (each needs an external account + the rebuild in Phase D)

FeatureExternal stepEnv var
Territory mapGoogle Cloud → Maps SDK for Android key + billing + restrict to com.madsales.atleatoEXPO_PUBLIC_GOOGLE_MAPS_API_KEY

Set whichever you're ready for (skip the rest — the app fails safe without them): 
eas env:create --environment preview --name EXPO_PUBLIC_GOOGLE_MAPS_API_KEY --value <key> --visibility plaintext
eas env:create --environment preview --name EXPO_PUBLIC_BRANCH_KEY --value key_live_xxx --visibility plaintext
eas env:create --environment preview --name EXPO_PUBLIC_ENABLE_HEALTH --value 1 --visibility plaintext

Repeat with --environment production before a Play Store build. Branch + smartwatch only fully work on Play Store installs / real devices, not sideloaded APKs.

Phase D — Rebuild the app

eas build -p android --profile preview

Picks up: every JS fix from this session (referral loop, coach crash, tab bar, stat strip, pick-exercise routing, full-screen calls) + whichever native features you enabled in Phase C. Uninstall the old app before installing the new APK.

Phase E — Verify

  1. Drip: curl -X POST https://kbldncrurztfwlqzajen.functions.supabase.co/send-drip-emails -H "x-cron-secret: <secret-2>" → returns {ok:true,sent:{...}}
  2. Counter: open atleato.com → scarcity banner shows a real "X of 500" (or static text if no paid orders yet).
  3. Referral reward: in-app referral screen loads its count without error.
  4. Admin: dashboard source breakdown shows UTM rows once traffic arrives.
Minimum to launch the waitlist: Phase A + B + D. Phase C is whenever you've set up those accounts. Don't block promotion on C.
